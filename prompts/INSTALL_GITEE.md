# 中国大陆兼容版安装提示词（Gitee）

适用于无法稳定访问 GitHub、但可以访问 Gitee 的用户。把下面正文和公开 Gitee 模板地址一起发给一款能操作本机文件与终端的 Agent。

---

请帮我搭建一套跨电脑、跨系统、跨 AI Agent 的共享记忆。我无法稳定访问 GitHub，请使用这个公开 Gitee 模板：`<PUBLIC_GITEE_TEMPLATE_URL>`。

我不是技术用户。请实际完成安装，不要只给 Git 教程，也不要让我手动输入 Git 命令。

## 最终结果

使用普通 Markdown 保存我主动提供的上下文，并使用一个我能够稳定访问的 **Private Git 远端仓库** 在不同设备之间同步。优先使用 Gitee Private 仓库；如果当前 Agent 已经安全接入了其他我指定的私有 Git 服务，也可以使用，但必须先解释差异并得到我的确认。

## 安全要求

- 公开模板与个人记忆必须是两个仓库。绝不能把我的个人内容写回公开模板。
- 个人记忆远端必须明确验证为 Private；无法验证就停止上传。
- 只在 Gitee 官方页面完成登录和授权。不得向我索取密码、短信验证码、Token、私钥或 Cookie。
- 不得为了自动化要求我把访问令牌发进聊天。如果 Gitee 当前没有适合的官方无凭据自动授权流程，就清楚地带我在官方网页创建一个 Private 空仓库；这是允许保留的一步人工操作。
- 不得删除、覆盖、强制重置已有目录或文件。
- 不保存密码、API Key、Token、验证码、证件、银行税务资料、详细医疗资料或第三方隐私。

## 执行流程

1. 识别操作系统、当前 Agent 和项目级说明入口。
2. 检查 Git；缺失时只从系统包管理器或官方来源安装，并先征得我确认。
3. 克隆公开 Gitee 模板，或下载模板后在新的本地目录中初始化。
4. 引导我在 Gitee 官方网站登录。若 Agent 无法安全创建远端，就让我只完成“新建 Private 空仓库”这一步，不让我配置 Git。
5. 读取 Private 仓库的远端地址并连接本地工作区。
6. 再次通过官方页面或 API 明确验证仓库为 Private，然后才允许写入个人上下文。
7. 完整遵循模板中的 `prompts/INSTALL.md`，但把其中 GitHub 专用动作替换为等价的 Gitee/Git 动作。
8. 安装中立 Markdown、当前 Agent 入口和 `skills/shared-memory/SKILL.md`。
9. 逐题进行安全访谈，先显示预览，经我确认后再写入。
10. 做敏感信息检查，拉取、提交、推送并验证。
11. 生成已经填好 Private Gitee 仓库地址的第二设备接入提示词。

如果某一步不能像 GitHub 版本那样全自动，请明确告诉我“只需要点击哪里”，不要假装完成，也不要通过索取长期凭据来绕过安全边界。

现在先用不超过 6 句话解释计划和需要我亲自完成的步骤，再开始环境检查。
